# 5.1 数据接入与索引模块

本目录实现赛题三系统设计方案中的 5.1 数据接入与索引模块。

目标：

- 将 PaSa 查询集转换为统一的 `queries`、`gold_labels`、`eval_sets`。
- 将 PaSa 论文库转换为统一的 `papers`、`paper_chunks`。
- 提供 MySQL 表结构。
- 提供 Elasticsearch 索引初始化和批量导入脚本。
- 提供 Qdrant sparse baseline 集合初始化、批量导入和连接验证脚本。

## 快速验证

数据库配置统一放在：

```text
../config/database.env
```

所有 `scholar_ingest` 和 `python -m scholar_app.cli --backend database|auto` 命令会自动读取这个文件；也可以通过 `SCHOLAR_SEARCH_CONFIG` 指向另一个配置文件。命令行环境变量优先级最高，可临时覆盖配置文件里的单项。

在本目录下运行：

```bash
python -m scholar_ingest.cli doctor
python -m scholar_ingest.cli convert-pasa --limit 3
python -m scholar_ingest.cli init-qdrant --sparse --collection saiti3_paper_chunks_v1
```

当前 `scholar_ingest.cli init-qdrant --sparse` 会创建 lexical sparse baseline collection；如果要创建 dense collection，可省略 `--sparse` 并传 `--vector-size`。

当前实验环境的 MySQL、Elasticsearch、Qdrant 连接信息已经集中在根配置文件中。

默认不会移动原始数据。派生数据写入：

```text
data_processed/
```

## 数据库初始化与真实接入

本模块提供 MySQL、Elasticsearch、Qdrant 的真实初始化、导入、验证和检索 smoke test。默认初始化是非破坏性的：只创建不存在的 database/table/index/collection。只有显式传 `--reset` 才会删除并重建已有数据结构。

非破坏性初始化全部数据库：

```bash
python -m scholar_ingest.cli init-all
```

分别初始化：

```bash
python -m scholar_ingest.cli init-mysql
python -m scholar_ingest.cli init-es
python -m scholar_ingest.cli init-qdrant --sparse
```

查看连接和数据量：

```bash
python -m scholar_ingest.cli doctor --check-mysql --check-es --check-qdrant
python -m scholar_ingest.cli verify-all
```

导入本地 `data_processed` smoke 数据：

```bash
python -m scholar_ingest.cli load-mysql --limit 3
python -m scholar_ingest.cli load-es --kind papers --index saiti3_papers_v1
python -m scholar_ingest.cli load-es --kind chunks --index saiti3_paper_chunks_v1
python -m scholar_ingest.cli load-qdrant --limit 25
```

真实检索 smoke test：

```bash
python -m scholar_ingest.cli search-es --kind papers --query "image retrieval" --top-k 5
python -m scholar_ingest.cli search-es --kind chunks --query "image retrieval" --top-k 5
python -m scholar_ingest.cli search-qdrant --query "image retrieval" --top-k 5
```

## 数据边界

`AutoScholarQuery/*.jsonl` 和 `RealScholarQuery/test.jsonl` 是查询集与 gold 标注，不是检索结果。

检索阶段不能读取 `answer_arxiv_id`；它只能在离线评测时用于 Recall、Precision、F1 计算。

论文候选池来自：

- `paper_database/id2paper.json`
- `paper_database/cs_paper_2nd.zip`
- 后续在线 API：Semantic Scholar、OpenAlex、PubMed 等

## 服务分工

MySQL：

- 保存权威元数据、gold labels、实验记录、成本日志。

Elasticsearch：

- 保存 BM25 文本检索索引、标题索引、chunk 索引。

Qdrant：

- 保存 `paper_chunks` 的 lexical sparse baseline 向量点，用于先跑通向量库隔离、回表和 hybrid 检索链路。
- 接入 bge / Qwen embedding 服务后，可新建 dense collection 或增加 dense vector name 承担真正语义向量召回。

## 远端全量导入

服务器 `cu02` 上的全量导入目录：

```text
/data/csp/scripts/server_ingest.py
/data/csp/scripts/schema.sql
/data/csp/data_raw/pasa/data
/data/csp/data_processed
/data/csp/logs
```

推荐执行顺序：

```bash
cd /data/csp
python3 /data/csp/scripts/server_ingest.py convert
python3 /data/csp/scripts/server_ingest.py reset-mysql
python3 /data/csp/scripts/server_ingest.py load-mysql --batch-size 500 --paper-batch-size 500 --chunk-batch-size 100
python3 /data/csp/scripts/server_ingest.py reset-es
python3 /data/csp/scripts/server_ingest.py load-es --batch-size 1000
python3 /data/csp/scripts/server_ingest.py init-qdrant
QDRANT_URL=http://11.11.11.2:6333 python3 /data/csp/scripts/server_ingest.py load-qdrant --batch-size 1024 --vector-size 65536
python3 /data/csp/scripts/server_ingest.py verify
```

`load-qdrant --vector-size` 在 sparse baseline 中表示 hash 特征空间维度，不是 dense embedding 维度。当前稳定参数为 `65536` 维、batch `1024`。

Qdrant 支持按 JSONL 行号恢复或分片导入：

```bash
QDRANT_URL=http://11.11.11.2:6333 python3 /data/csp/scripts/server_ingest.py load-qdrant \
  --batch-size 1024 \
  --vector-size 65536 \
  --start-line 1000001 \
  --end-line 2000000
```

当前远端采用直接读取分片文件的方式继续导入 Qdrant，分片文件位于：

```text
/data/csp/data_processed/qdrant_shards/chunks_part_*.jsonl
```

示例：

```bash
QDRANT_URL=http://11.11.11.2:6333 python3 /data/csp/scripts/server_ingest.py load-qdrant \
  --input-file /data/csp/data_processed/qdrant_shards/chunks_part_1.jsonl \
  --batch-size 512 \
  --vector-size 65536
```

说明：本机自动关机和自动收尾 watcher 已停止；后续不会自动关机。
