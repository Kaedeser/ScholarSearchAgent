# 赛题三数据库数据结构说明

本文档说明 5.1 数据接入与索引模块涉及的各类数据库与文件型数据结构。

当前涉及五类存储：

| 存储 | 服务 / 位置 | 主要用途 |
| --- | --- | --- |
| MySQL | `scholar_search` | 元数据、查询集、gold 标注、实验记录、成本日志 |
| Elasticsearch | `saiti3_papers_v1`、`saiti3_paper_chunks_v1` | BM25 / 文本检索索引 |
| Qdrant | `saiti3_paper_chunks_v1` collection | chunk lexical sparse baseline 向量检索 |
| Neo4j | physical database `neo4j` / logical graph `paper` | 论文、章节、引用、概念关系图谱 |
| 本地 JSONL | `data_processed/` | 数据转换中间产物，便于导入和复现实验 |

## 1. 总体数据流

```text
PaSa 论文库 + AutoScholarQuery / RealScholarQuery 查询集
  -> 转换脚本
    -> data_processed/*.jsonl
      -> MySQL: 元数据、查询、gold、评测与实验记录
      -> Elasticsearch: papers / paper_chunks 文本检索索引
      -> Qdrant: paper_chunks lexical sparse baseline 向量集合
      -> Neo4j: Paper / Section / ReferenceMention / Concept 图谱
```

检索阶段不能读取 `gold_labels` 或 `answer_arxiv_id`。这些字段只用于最终离线评测。

当前导入边界：

- 应进入召回语料：PaSa 论文库生成的 `papers.jsonl`、`paper_chunks.jsonl`。
- 应进入评测事实表：AutoScholarQuery / RealScholarQuery 的 `queries.jsonl`、`gold_labels.jsonl`、`eval_sets.jsonl`。
- 不应进入召回语料：AutoScholarQuery 的答案字段、`gold_labels`、`sft_crawler`、`sft_selector`、`asta-bench-dataset` 等训练或评测数据。否则会把答案泄露到召回链路。

Qdrant 用于向量检索。当前全量导入采用 lexical sparse baseline，用于先跑通向量库隔离、过滤、回表和 hybrid 检索链路；它不是最终语义 embedding。

| --- | --- |

| `sparse_vectors` | `text` |
| `hash dimensions` | `65536` |

当前 point 结构：

```json
{
  "id": "UUID5(namespace, chunk_id)",
  "vector": {
    "text": {
      "indices": [101, 2048, 90991],
      "values": [1.0, 2.0, 1.0]
    }
  },
  "payload": {
    "chunk_id": "arxiv:2404.00001#chunk:0",
    "paper_id": "arxiv:2404.00001",
    "chunk_index": 0,
    "chunk_type": "title_abstract",
    "section_title": null,
    "source": "pasa",
    "token_estimate": 128
  }
}
```

payload 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `chunk_id` | string | chunk 唯一 ID |
| `paper_id` | string | 论文 ID |
| `chunk_index` | integer | 论文内 chunk 序号 |
| `chunk_type` | string | chunk 类型 |
| `section_title` | string / null | 章节标题 |
| `source` | string | 数据来源 |
| `token_estimate` | integer | token 估计 |

注意：

- Qdrant REST point id 使用 UUID5，由 `chunk_id` 稳定生成；业务回表和跨库对齐使用 payload 中的 `chunk_id`。
- 当前 `text` sparse vector 是 lexical hash baseline，hash 特征空间为 `65536`。
- Qdrant 只保存 sparse vector 与轻量 payload，不保存完整 chunk 文本；完整文本仍从 MySQL `paper_chunks.text` 或 Elasticsearch `saiti3_paper_chunks_v1.text` 回表获取。
- 当前全量补齐记录：先按分片导入 `paper_chunks.jsonl`，最后扫描前 600,000 行发现 `300001-600000` 区间仍缺 37,824 个 point，仅补导缺失 JSONL 后达到 `points_count = indexed_vectors_count = 5029139`。
- 接入 bge / Qwen embedding 后，建议新建 dense collection 或增加 dense vector name，并重新批量 upsert 语义向量。

## 5. Neo4j 图谱结构

Neo4j 用于论文结构关系增强，不承担全文检索或向量检索职责。当前 Neo4j 服务不创建独立物理库 `paper`，而是在默认物理库 `neo4j` 中用逻辑图谱隔离：

```text
physical database: neo4j
logical graph_name: paper
entry node: (:Graph {name: "paper", kind: "paper_kg"})
main paper scope: (:Graph {name: "paper"})-[:CONTAINS]->(:Paper)
```

当前图谱规模：

| 类型 | 标签 / 关系 | 数量 | 说明 |
| --- | --- | ---: | --- |
| 节点 | `Graph` | 1 | 逻辑图谱入口 |
| 节点 | `Paper` | 571,468 | 569,265 个主论文节点 + 2,203 个引用占位论文节点 |
| 节点 | `Section` | 4,459,392 | 论文章节 |
| 节点 | `ReferenceMention` | 19,918,798 | section 中的参考文献提及 |
| 节点 | `Concept` | 2,998,217 | 规则抽取概念 |
| 节点 | `Chunk` | 0 | 已预留约束和导入命令，当前未导入 |
| 关系 | `CONTAINS` | 569,265 | `Graph -> Paper`，只连接主论文 |
| 关系 | `HAS_SECTION` | 4,459,392 | `Paper -> Section` |
| 关系 | `MENTIONS_REFERENCE` | 19,918,798 | `Section -> ReferenceMention` |
| 关系 | `RESOLVES_TO` | 7,081,050 | `ReferenceMention -> Paper`，解析成功的引用 |
| 关系 | `CITES` | 7,081,050 | `Paper -> Paper` 论文级引用边 |
| 关系 | `MENTIONS_CONCEPT` | 6,328,400 | `Paper -> Concept` |

核心节点：

| 标签 | 关键属性 | 来源 / 用途 |
| --- | --- | --- |
| `Graph` | `name`、`kind`、`updated_at` | 逻辑图谱入口 |
| `Paper` | `paper_id`、`arxiv_id`、`title`、`year`、`source`、`graph_name` | 来自 MySQL `papers`，引用解析失败或只在参考文献中出现的论文会作为占位节点 |
| `Section` | `section_id`、`paper_id`、`section_title`、`section_role`、`order_index`、`graph_name` | 来自 PaSa 全文 section |
| `ReferenceMention` | `mention_id`、`source_paper_id`、`section_id`、`reference_title`、`target_paper_id`、`match_method`、`match_score`、`graph_name` | 表示某个 section 中出现的一条参考文献 |
| `Concept` | `concept_id`、`name`、`normalized_name`、`graph_name` | 从标题、摘要、章节标题等文本中规则抽取 |
| `Chunk` | `chunk_id`、`paper_id`、`chunk_index`、`chunk_type`、`text_preview`、`graph_name` | 可选节点；当前数量为 0 |

典型用法：

- ES / Qdrant 先召回 chunk 或 paper，得到 `paper_id`。
- 用 `paper_id` 进入 Neo4j `Paper` 节点，扩展 `CITES`、`MENTIONS_CONCEPT`、`HAS_SECTION`。
- 图谱扩展结果作为重排特征或解释证据，例如引用方向、引用章节、概念重合、引用解析置信度。
- 当前不建议把 5,029,139 个完整 chunk 写入 Neo4j；chunk 级召回应由 ES / Qdrant 承担，Neo4j 负责 paper 级结构增强。

## 7. ID 对齐规则

统一 ID 优先级：

1. arXiv ID：`arxiv:<normalized_arxiv_id>`
2. DOI：后续可扩展为 `doi:<normalized_doi>`
3. Semantic Scholar corpusId：后续可扩展为 `s2:<corpus_id>`
4. OpenAlex ID：后续可扩展为 `openalex:<id>`
5. title hash：无法获得标准 ID 时使用 `title:<sha1_prefix>`

当前 PaSa 数据主要使用 arXiv ID，因此 `paper_id` 默认形如：

```text
arxiv:2404.00001
```

## 8. 数据库之间的关联关系

```text
MySQL papers.paper_id
  = Elasticsearch saiti3_papers_v1.paper_id
  = Elasticsearch saiti3_paper_chunks_v1.paper_id
  = Qdrant payload.paper_id
  = Neo4j (:Paper).paper_id

MySQL paper_chunks.chunk_id
  = Elasticsearch saiti3_paper_chunks_v1.chunk_id
  = Qdrant payload.chunk_id

Qdrant point id
  = UUID5(namespace, chunk_id)

MySQL queries.qid
  = MySQL gold_labels.qid
  = MySQL eval_sets.qid
  = MySQL search_runs.qid
  = MySQL search_results.qid
```

### 9.3 完整性结论

从“全量构建 PaSa 检索底座”的角度，本地脚本已经覆盖：

```text
PaSa 原始数据
  -> data_processed JSONL
  -> MySQL 核心事实表
  -> Elasticsearch papers / chunks
  -> Qdrant chunk sparse vectors
  -> Neo4j paper knowledge graph
```

从“可长期运维”的角度，还建议补三类脚本能力：

1. 增加 Qdrant missing-only 补导命令：按 `chunk_id -> UUID5 point id` 扫描 collection，仅生成并 upsert 缺失 point。
2. 增加导入审计写入：每次导入写 `ingestion_runs`，记录输入文件、范围、batch、耗时、成功/失败计数。
3. 增加扩展表填充：自动汇总 `datasets`，并把 arXiv / DOI / corpusId / OpenAlex 等统一写入 `paper_identifiers`。

## 10. 后续扩展建议

- 为 MySQL 增加只读/读写分离的业务账户，避免长期使用 `root`。
- 为 Qdrant 写入 embedding 后，增加 payload index，例如 `paper_id`、`chunk_type`、`year`。
- 为 Elasticsearch 增加 alias：`saiti3_papers_current`、`saiti3_chunks_current`。
- 如果引入在线 API，扩展 `paper_identifiers` 保存 DOI、Semantic Scholar corpusId、OpenAlex ID。
- 如果引入 reranker，扩展 `search_results.reason` 或新增 `rerank_logs` 保存精排解释和分数。
